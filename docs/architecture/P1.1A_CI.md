# Kiến trúc P1.1A — tích hợp liên tục và ảnh theo commit

## 1. Mục tiêu và trạng thái

P1.1A tạo một quy trình tích hợp liên tục (CI) có thể lặp lại: lấy mã nguồn, dùng đúng phiên bản Node.js, cài phụ thuộc từ lockfile, kiểm tra cấu hình, build/test toàn hệ thống, sau đó dựng ảnh App A/App B gắn với commit.

Tại ngày 12/10/2026, cấu hình và script đã được kiểm thử cục bộ. Workflow chưa có kết quả chạy trên GitHub vì repository chưa gắn remote. Do đó tài liệu này không tuyên bố CI trên GitHub đã hoạt động thật.

## 2. Phạm vi P1.1A

Đã thực hiện:

- Workflow chạy khi push vào `main`, pull request hoặc kích hoạt thủ công.
- Quyền `GITHUB_TOKEN` chỉ là `contents: read`.
- Node.js được ghim qua `.node-version`; npm dùng ba lockfile đã commit.
- Ba GitHub Action được ghim bằng commit SHA đầy đủ.
- Workflow chạy production build, unit test và toàn bộ regression P0.
- App A/App B được build với tag `sha-<12 ký tự đầu của commit>`.
- Mỗi ảnh có nhãn `org.opencontainers.image.revision` chứa commit đầy đủ và `org.opencontainers.image.version` chứa tag phiên bản.
- `image-manifest.json` ghi commit, tag, nền tảng và image ID; artifact được giữ 14 ngày.
- Không dùng secret thật; tài khoản và secret trong job chỉ là dữ liệu CI giả, cố định và không dùng ngoài runner tạm thời.

Chưa thuộc P1.1A:

- Đăng nhập hoặc đẩy ảnh lên GitHub Container Registry.
- Registry digest, chữ ký ảnh hoặc Software Bill of Materials (SBOM).
- Gọi Control API/Runner trên máy phát triển hoặc VPS từ GitHub.
- Tự động triển khai sau khi build.
- Cho phép người dùng cung cấp repository hoặc Dockerfile tùy ý.

## 3. Luồng xử lý

```text
Push / Pull request / Chạy thủ công
                 |
                 v
       GitHub-hosted runner tạm thời
                 |
        +--------+---------+
        |                  |
        v                  v
  npm ci từ lockfile   docker compose config
        |                  |
        +--------+---------+
                 v
      unit test + production build
                 |
                 v
       dựng stack + regression P0
                 |
                 v
      build App A/B theo commit SHA
                 |
                 v
       kiểm tra nhãn + image manifest
                 |
                 v
       artifact minh chứng (14 ngày)
```

Quy trình kết thúc ở artifact. Không có mũi tên từ GitHub runner đến máy/VPS ở P1.1A.

## 4. Quy ước nhận dạng ảnh

Ví dụ với commit `ac25ecb2f218313af7b2ba5c5dde10ba30d5f17c`:

```text
mini-paas/app-a:sha-ac25ecb2f218
mini-paas/app-b:sha-ac25ecb2f218
```

Tag rút gọn giúp đọc log, còn nhãn OCI giữ commit đầy đủ để truy vết. Manifest phải giữ cả `reference` và `imageId`.

`imageId` là định danh nội dung trong Docker Engine của runner và có thể khác giữa `linux/arm64` và `linux/amd64`. Nó chưa phải digest của ảnh trong registry. P1.1B chỉ được ghi “registry digest” sau khi ảnh đã được đẩy lên registry và đọc lại digest từ registry.

## 5. Ranh giới bảo mật

- Workflow không dùng `pull_request_target`, không nhận secret triển khai và không có quyền ghi package.
- Checkout không lưu credential Git sau bước lấy mã nguồn (`persist-credentials: false`).
- Pull request có thể thực thi code của repository trong Docker trên GitHub-hosted runner tạm thời, nhưng không được cấp đường vào VPS hay Docker host nội bộ.
- Giá trị `ADMIN_PASSWORD` và `RUNNER_SHARED_SECRET` trong workflow được đặt tên rõ là dữ liệu CI, không được tái sử dụng ở môi trường thật.
- Artifact không chứa `.env`, cookie hoặc log request đầy đủ; chỉ có manifest, phiên bản công cụ và trạng thái Compose.
- Ở P1.1B, thao tác triển khai phải tiếp tục đi qua allowlist của Runner; CI không được nhận Docker socket hoặc SSH host tùy ý từ dữ liệu pull request.

## 6. Khả năng tái hiện

- `.node-version` ghim Node.js `24.12.0`.
- `npm ci` bắt buộc dùng `package-lock.json` của từng thành phần.
- Ảnh nền trong Dockerfile đã ghim digest.
- GitHub Actions dùng commit SHA đầy đủ, kèm chú thích phiên bản dễ rà soát.
- `ubuntu-24.04` được dùng thay cho `ubuntu-latest` để tránh thay đổi hệ điều hành ngoài ý muốn.

Các Action chính thức được chọn từ bản phát hành hiện hành tại thời điểm cấu hình: [actions/checkout v7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1), [actions/setup-node v7.1.0](https://github.com/actions/setup-node/releases/tag/v7.1.0) và [actions/upload-artifact v7.0.2](https://github.com/actions/upload-artifact/releases/tag/v7.0.2).

## 7. Kiểm thử và bằng chứng

Kiểm thử cục bộ:

```bash
make test-p1-1a
```

Tiêu chí:

1. Từ chối commit SHA sai định dạng trước khi gọi Docker build.
2. Dựng đủ App A/App B theo tag của commit.
3. Manifest dùng schema đã xác định và ghi rõ `local-only`.
4. Image ID trong manifest trùng ảnh Docker thực tế.
5. Nhãn revision/version truy vết đúng về commit.

Nghiệm thu GitHub chỉ đạt khi có một workflow run thành công và tải được artifact chứa `image-manifest.json`. Kết quả local không thay thế bằng chứng đó.

## 8. Điều kiện mở P1.1B

P1.1B chỉ bắt đầu sau khi:

1. Repository GitHub và remote đã được xác nhận.
2. Nhóm quyết định chế độ public/private của repository và package.
3. P1.1A chạy thành công trên GitHub.
4. Chọn registry, quy tắc lưu tag và thời gian giữ ảnh.
5. Chốt cách VPS nhận một image đã cho phép mà không công khai Docker API hay lưu secret trong Git.
