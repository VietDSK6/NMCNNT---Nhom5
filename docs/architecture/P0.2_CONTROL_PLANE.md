# Kiến trúc P0.2A — Nền tảng control plane

## 1. Phạm vi đã triển khai

P0.2A bổ sung lớp quản trị lên nền P0.1 nhưng chưa trao quyền điều khiển Docker cho API. Mục tiêu của mốc này là dựng một đường đi hoàn chỉnh và kiểm thử được:

```text
Trình duyệt
    |
    v
Nginx Gateway :8080
    |-- / ----------------------> Dashboard
    |-- /api/* -----------------> Control API ---> SQLite volume
    |-- /apps/app-a/* ----------> App A
    `-- /apps/app-b/* ----------> App B
```

Dashboard gọi Control API cùng origin. Control API đọc danh mục ứng dụng từ SQLite, sau đó kiểm tra health và version của từng ứng dụng qua Gateway. Cách đi vòng qua Gateway có chủ đích: kết quả quan sát phản ánh đúng đường truy cập mà người dùng thật sử dụng, gồm cả định tuyến Nginx.

## 2. Ranh giới mạng và quyền

| Thành phần | Mạng | Cổng ra host | Quyền Docker |
|---|---|---:|---|
| Gateway | `edge`, `control` | `127.0.0.1:8080` | Không |
| Dashboard | `control` | Không | Không |
| Control API | `control` | Không | Không |
| App A, App B | `edge` | Không | Không |

Mạng `control` đặt `internal: true`. Chỉ Gateway có mặt ở cả hai mạng để chuyển tiếp request. Docker socket không được mount vào bất kỳ container nào.

Đây mới là control plane nền tảng. Deployment Runner ở bước kế tiếp sẽ là thành phần quyền cao duy nhất, nhận action/app/version từ danh sách cho phép. API hiện không chạy command và không thể dừng hay thay image container.

## 3. Mô hình dữ liệu SQLite

Migration đầu tiên tạo bốn bảng:

- `users`: tài khoản quản trị và password hash bằng `scrypt` với salt riêng.
- `sessions`: hash SHA-256 của session token, thời điểm tạo/hết hạn và lần truy cập gần nhất.
- `applications`: route, health path, version path và desired version.
- `audit_events`: người thực hiện, action, kết quả, IP và thời gian.

Session token thô chỉ nằm trong cookie phía trình duyệt; SQLite chỉ giữ token hash. Khi đổi `ADMIN_PASSWORD` và khởi động lại API, password hash được thay, đồng thời các phiên cũ của tài khoản bị xóa.

SQLite nằm trong named volume `mini-paas-control-data`, tách khỏi filesystem chỉ đọc của container. P0.2A chưa có chức năng backup/restore volume; nội dung này thuộc mốc sau và T08.

## 4. Hợp đồng API đã có

| Method | Endpoint | Xác thực | Mục đích |
|---|---|---|---|
| GET | `/api/health` | Không | Health check của Control API |
| POST | `/api/v1/auth/login` | Không | Tạo session quản trị |
| GET | `/api/v1/auth/session` | Có | Kiểm tra phiên hiện tại |
| POST | `/api/v1/auth/logout` | Có | Hủy session hiện tại |
| GET | `/api/v1/applications` | Có | Metadata, health và version quan sát được |
| GET | `/api/v1/audit-events?limit=N` | Có | Audit gần nhất, tối đa 100 bản ghi |

API dùng JSON Schema của Fastify để giới hạn body/query. Body tối đa 64 KiB. POST từ Origin khác `PUBLIC_ORIGIN` bị trả 403. Không bật CORS.

## 5. Ba lớp trạng thái

Dashboard cố ý phân biệt:

1. `desiredVersion`: cấu hình mong muốn từ SQLite/Compose.
2. `observedVersion` và `health`: dữ liệu thực đọc qua HTTP Gateway.
3. `runtime.status`: hiện là `not_integrated` vì chưa có Runner/Docker inspection.

Không được dùng health HTTP để tuyên bố chắc chắn trạng thái Docker. Một endpoint có thể phản hồi trong khi metadata Docker khác kỳ vọng; ngược lại, container “running” không bảo đảm nghiệp vụ khỏe.

## 7. Giới hạn và bước kế tiếp

- Chưa có Deployment Runner, lifecycle action, log hay Docker stats.
- Module `node:sqlite` trong Node.js 24 phát cảnh báo thử nghiệm. Mã truy cập được cô lập trong `database.ts`; phải đánh giá lại trước release cuối.
- Chưa có chống brute force phân tán; môi trường P0.2 chỉ bind localhost. Khi đưa lên VPS cần HTTPS, giới hạn đăng nhập và cấu hình `PUBLIC_ORIGIN` theo domain.
- Một Gateway, một API, một SQLite và một host đều là điểm lỗi đơn.
- Dashboard không phải nguồn dữ liệu giám sát dài hạn; Prometheus/Grafana thuộc P1.

Bước P0.2B: thiết kế protocol API ↔ Runner, allowlist app/action/version, khóa thao tác theo app và operation state trước khi mount quyền Docker cho Runner.
